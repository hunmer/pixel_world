# 06 道具设计（Items）

> 本文档服务于**「交锋」**与**「抉择」**两大支柱——道具是玩家在战场上**可消耗的资源**，每一次使用都是不可逆取舍；同时通过「源脉相关稀有道具」呼应 [00 设计支柱](00_design_pillars.md) 的「魔法稀缺」硬约束。

> 元素/系别对应世界观中的源脉分支，详见 [01 世界观·源脉体系](01_worldview.md)；装备与职业 `weaponType` 的对应关系详见 [03 职业](03_professions.md)。

---

## 〇、本次重大更新摘要（v2）

相对 v1（25 个道具、装备共用 `type:"equip"`），本版新增/重构如下内容：

1. **装备分类解耦**：将原 `type:"equip"` 拆分为 **`type:"weapon"`** 与 **`type:"armor"`** 两个独立分类，并新增饰品 `type:"accessory"`。武器绑定 `weaponType`（限制装备职业）、防具绑定 `slot`（防具槽位 body/helm/shield），让装备管理更结构化。
2. **武器耐久度系统**：所有武器引入 `durability`（当前耐久）+ `maxDurability`（最大耐久）字段。每次攻击 -1，耐久归零时武器**损坏（broken）**，攻击力大幅下降但**不消失**——玩家必须修复才能恢复，呼应 reinforcement-feedback-systems 的**资源维护负担**。
3. **修复系统**：两类修复路径——**金币修复**（商店付费）+ **同类武器叠加修复**（用一把同名或同类武器喂给另一把）。详见第十一节。
4. **道具总览扩充**：从 25 个 → **52 个**。武器 14 把（覆盖 6 种 weaponType）、防具 12 件（body/helm/shield 三槽）、饰品 6 件、消耗品 10 个、投掷物 6 个、任务道具 4 个。

> 字段对齐：所有新字段（`durability / maxDurability / slot / repairCost` 等）需在 `items.json` 数据层补全，详见 [数据迁移备忘](#十三数据迁移备忘对齐现有-itemsjson)。

## 一、设计原则（引用 Game Design Skill）

| 原理 | 在本设计中的体现 |
|------|------------------|
| **reinforcement-feedback-systems**（奖惩反馈） | 消耗品用「uses 耗尽即消失」形成**负惩罚**（Negative Punishment：移除奖励），塑造「不能无脑刷药」的行为；源脉传说道具用「永久 -1 属性」施加**正向惩罚**（Positive Punishment），让「滥用魔法」有代价。**耐久度系统**则把「攻击」这个最频繁的正强化行为**附加维护负担**——每次交锋都在悄悄消耗一件有限资源，逼玩家算「这一刀值不值得砍」。 |
| **character-optimization-design**（属性关联防 min/max） | 装备采用**互联属性**（Interconnected Attributes）：高攻武器降命中、高防具降移动力，使「堆单一属性」自然受挫，防止 twinking（低级角色套高级装备）。**耐久度**则是第二条反 min/max 防线：稀有武器耐久更低（传说武器 maxDur=20 vs 普通武器 40），让「一把传说剑通关」不成立——王牌必须保养。 |
| **doubling-halving-balance**（快速平衡） | 数值区间先用 2×/0.5× 定锚（如药剂 heal_hp 在 20/35/60 三档、武器耐久在 40/30/20 三档），再微调；详见第八节自检。 |
| **flow-state-design-framework**（心流） | 道具获取节奏配合技能解锁：每章引入 1 类新道具机制，避免一上来就给全图鉴造成「技能过高→焦虑」。耐久度系统也按章节递进——第 1 章只给耐久 40 的铁剑，让玩家在低压力下学会「修复」这个习惯，再逐步引入低耐久的精良/传说武器。 |
| **synergy-thematic-design**（主题协同） | 耐久度 + 修复系统的主题叙事是「**战争磨损一切**」——刀剑会卷刃、甲胄会凹陷、源脉法器会被魔力侵蚀。这呼应「战争没有赢家，只有活下来的人」的核心主题，让「整备→战斗→整备」的核心循环天然带上保养环节。 |
| **player-psychology-decisions**（决策设计 / 囤积行为） | 耐久度直接打击玩家**囤积癖**：传说武器不修会变废铁，逼玩家「现在用」而非「留着不用」。修复系统的两种路径制造**三角性决策**：花金币（经济成本）还是花同类武器（库存成本）——没有免费午餐。 |

## 二、稀有度系统

定义 **4 级稀有度**，稀有度与「数值上限 / 获取难度 / 副作用 / **耐久度**」四者挂钩。

| 稀有度 | 英文 | 颜色 | 数值倍率 | 武器耐久基准 | 获取方式 | 副作用约定 |
|--------|------|------|----------|--------------|----------|------------|
| 普通 | Common | 灰 | ×1.0（基准） | **40**（最耐用） | 商店常驻、白名敌人常规掉落 | 无 |
| 精良 | Fine | 绿 | ×1.5 | **30** | 精英敌人掉落、章节商店限定 | 无或极轻 |
| 史诗 | Epic | 蓝 | ×2.0 | **25** | 关卡宝箱、分支剧情奖励、BOSS 掉落 | 可能有轻代价（如 uses=1） |
| 传说 | Legendary | 金 | ×3.0 或特殊机制 | **20**（最锋利也最脆） | 隐藏关卡、关键抉择、源脉相关 | **必有代价**（永久属性损减 / uses=1 / 触发剧情后果） |

> **设计锚点（doubling-halving）**：普通药剂 heal_hp=20，精良=35（≈1.75×），史诗=60（≈3×，因附带 MP 回复故总效用更高）。先用 2× 试探再回调。
>
> **耐久度逆相关设计（character-optimization-design）**：**越强的武器耐久越低**——这是反 min/max 的第二道闸。普通铁剑耐久 40 可砍 40 次，传说源脉法杖耐久 20 只能放 20 次大招。玩家若想「一把传说剑砍穿全游戏」，必须频繁修复（高昂金币 / 稀缺同类武器），让「滥用王牌」有持续代价。

## 三、道具分类总表（52 个）

> 字段严格对齐 `godot/data/items.json` 的基础字段：`id / name / desc / type / target / effect / power / range / uses`。
> **v2 分类解耦**：
> - 消耗品：`type:"consumable"` / `type:"buff"`
> - 投掷物：`type:"throwable"`
> - **武器**：`type:"weapon"`（原 `type:"equip"` 的武器子集，新增耐久字段）
> - **防具**：`type:"armor"`（原 `type:"equip"` 的防具子集，新增 `slot` 字段）
> - **饰品**：`type:"accessory"`（新增，无槽位冲突，可同时穿戴一件）
> - 任务道具：`type:"quest"`
>
> `weaponType` 取值对齐 `professions.json`：`sword / lance / axe / bow / anima / staff`（`anima` 即魔导师魔法武器，与支柱中的 `magic` 同义）。

### 3.3 武器（weapon）— 14 个 ⚔️

> **v2 解耦核心分类**。武器统一走 `effect:"equip"` + `equipStat/equipValue`，并新增字段：
> - `weaponType`（限制装备职业，对齐 professions.json）
> - `hitBonusMod`（命中修正）
> - `durability`（当前耐久，初始 = maxDurability）
> - `maxDurability`（最大耐久）
> - `repairCost`（每点耐久的金币修复单价，见 [第十一节](#十一修复系统)）
>
> **耐久规则**：每次**主动攻击**（含反击触发）-1 durability。耐久归零（`broken` 状态）时：equipValue 降为 **×0.3**（取整）、hitBonusMod **-20**、**无法触发武器特技**（如源脉法杖的 mpCost -2 失效）。武器**不消失**，但必须修复才能恢复满效。

> **圣杖 holyScepter（新增）**：牧师/司祭专属。power 仅 +1（牧师本就不靠平 A）但 hit+8（辅助技能命中保障），且装备时治疗技能 power +3（由逻辑层特判）。耐久 35。**定位**：让辅助职业的「治疗 miss」不再是噩梦——牧师治疗 miss=队友死，圣杖的高命中是辅助系的「**责任保险**」。

### 3.4 防具（armor）— 12 件 🛡️

> **v2 解耦核心分类**。防具走 `effect:"equip"` + `equipStat/equipValue`，新增字段：
> - `slot`（防具槽位：`body` 身甲 / `helm` 头盔 / `shield` 盾牌）—— 一个单位**每个 slot 最多穿一件**，让防具有「配装深度」
> - `durability / maxDurability / repairCost`（同武器，但耐久规则不同，见下）
>
> **防具耐久规则（与武器不同）**：防具**不在攻击时消耗**，而是**每被命中一次 -1 durability**（无论是否破防）。这让重甲（被打次数多）反而耐久消耗更快——重甲单位必须更勤保养。防具 broken 时 equipValue 降为 ×0.5（取整），不再有额外惩罚。

### 3.5 饰品（accessory）— 6 件 💍

> **v2 新增分类**。饰品走 `effect:"equip"` + `equipStat/equipValue`，**无 slot 限制**（每个单位可同时戴 1 件饰品），**无耐久**（饰品是「魔法造物」，不磨损）。

## 四、消耗品代表作深入

### 4.1 生命药剂 hpPotion（普通 / 基准）
- **设计意图**：最基础的「交锋」续航。uses=3 意味着一个单位一关最多扛 3 次致命伤，迫使玩家在「保前排」与「省药给后排」间取舍（**三角性决策**）。
- **典型场景**：重骑士（hp 34）顶住隘口，每回合被打掉 12 HP，用 hpPotion 补 20 HP 维持战线。
- **搭配**：与 `guard`（铁壁 buff）连用——先开铁壁降受到伤害，再用药剂，省下 uses。

### 4.2 万能药剂 elixir（史诗 / 王牌续航）
- **设计意图**：同时回 HP+MP 但 **uses=1**，是「救命稻草」而非续航源。呼应 reinforcement-feedback-systems 的**变动奖励**——玩家不知道这关会不会掉第二个，因此不敢滥用。
- **典型场景**：魔导师 MP 见底、又被刺客切残时，一口 elixir 让其放出最后一个 `infernoBlade`（火系奥义）翻盘。
- **搭配**：保留给同时需要双资源的法师型单位（魔导师/牧师），物理职业用浪费。

### 4.3 凤凰羽 phoenixDown（精良 / 反 permadeath）
- **设计意图**：本作有永久死亡风险（见 [00 支柱·抉择](00_design_pillars.md)），phoenixDown 是**唯一**战斗中复活手段，uses=1 且稀有，让「角色阵亡」仍是高压惩罚但留一线生机——符合 reinforcement-feedback-systems 中「perma-death 易致玩家弃游，需 mitigation」的原则。
- **典型场景**：主力剑士被暴击秒杀，立即用 phoenixDown 以 50% HP 拉起，下回合撤退治疗。

### 4.4 磨刀石 whetstone（普通 / 耐久度系统的应急绷带）⭐新增
- **设计意图**：耐久度系统的**战场内即时修复**。uses=2，每次 +8 耐久，让玩家在长关卡里不必「打到一半武器坏了只能撤退」——但要精打细算：2 次/关 = 只能救 2 把武器。
- **典型场景**：主力剑士的铁剑耐久从 40 砍到 5（即将 broken），战斗还没结束，用磨刀石 +8 续命到 13，撑过最后 3 回合。
- **搭配策略**：
  - **优先给传说武器用**：源脉法杖耐久 20，磨刀石 +8 等于续了 40% 寿命，性价比最高。
  - **别给普通武器用**：铁剑耐久 40，修一次商店才 3 金/点（+8 = 24 金），磨刀石商店价 80 金——直接买磨刀石不划算，应回城修。这就是 doubling-halving 的**成本对比锚点**。

## 五、装备代表作深入

### 5.1 银弓 silverBow（精良 / 互联属性典范）
- **设计意图**：`power +3 / hitBonus +5`，刻意不给最高力增益，而是补命中。猎手本身 `skl=8`（高技）但 `power=6`（低力），银弓放大其「稳」而非「狠」，适配远程风筝战术。
- **反 min/max**：若玩家想堆「最高力远程」会发现银弓力不如重弩（+6），必须靠职业克制（[07 技能](07_skills.md) 物理 skill）补伤——防止单一装备通吃。

### 5.2 源脉法杖 sourceVeinStaff（传说 / 见第六节）

### 5.3 铁甲 ironArmor（普通 / 布阵代价）
- **设计意图**：`def +4 / mov -1`。重骑士原本 mov=4，穿上后 mov=3，几乎成了「固定炮台」。这强制玩家在战前整备时决定：这关要不要给重骑士穿甲？若地图大、需要机动作战，就不穿。
- **联动**：呼应「布阵」支柱——装备选择即战前布阵的一部分。

### 5.4 重弩 arbelos（史诗 / 射程与耐久的取舍）⭐新增
- **设计意图**：`power +6 / hit -5 / 射程 +1`，是弓系的「**重火力+超远射程**」王牌。但 25 耐久 + 10 金/点修复，让神射手「**开一枪就是烧一次钱**」。
- **典型场景**：神射手蹲在后排，用射程 5 安全狙击敌方魔导师（hp 16）——重弩 +6 配神射手 power 7 + 职业加成，一击 20+ 伤害秒杀。但 25 耐久意味着一关最多放 25 枪，硬仗要修 1-2 次。

### 5.5 板甲 plateArmor（精良 / 重甲之王与固定炮台）⭐新增
- **设计意图**：`def +6 / mov -2 / agility -2`，是 body 槽的最高防护，但双重惩罚让穿戴者「**走不动也躲不开**」。
- **典型场景**：重骑士穿板甲，def 从 11 飙到 17，普通物理几乎免疫——但 mov 从 4 降到 2，agility 从 3 降到 1，几乎必定被双击。**战术定位**：只能守隘口/护送关，不能机动野战。
- **搭配**：配小圆盾（agility +1）部分回血敏捷，配疾行靴（mov+1）部分回血机动——但两个槽都占了，helm 槽只能空着或戴皮盔（def+1）。**配装深度**就此展开。

## 六、源脉相关稀有道具（专题 / 呼应魔法稀缺）

> 这些道具是本设计对 [00 支柱·魔法稀缺](00_design_pillars.md) 的**最强表达**：它们提供「决定性魔法效果」，但**必有不可逆代价**，让玩家每次想用都心如刀割。引用 reinforcement-feedback-systems 的**正向惩罚**——给滥用加痛感。
>
> **v2 新增源脉装备耐久规则**：源脉装备（sourceVeinStaff/Crown/Aegis/Robe）的耐久**只能用源脉工具修复**——普通铁匠无法修，必须用 `repairKit` 或 `ancientForgeKey`（古锻炉）。这让源脉武器的「永久代价」之外多一层「维护代价」，让它们真正成为「**用得起修不起**」的王牌。

### 6.1 源脉法杖 sourceVeinStaff（传说装备）
```
weaponType: anima/staff
equipStat: power, equipValue: +4
hitBonusMod: +5
durability: 20, maxDurability: 20, repairCost: 15（且仅源脉工具可修）
特殊: 装备者所有 fire/water/earth/wind/light/dark 系技能 mpCost -2（最低 1）
代价: 装备者每关开始时 -2 HP（源脉侵蚀），且 res 永久 -1（戴上即生效）
```
- **叙事**：杖身封存着一缕源脉碎片，持续向持有者灌注魔力，也持续灼烧其血肉。
- **战术定位**：让一个法师变成「每关多放 1 个大招」的王牌，但牺牲生存（res -1 对法师是致命的，因为法师 hp 低、靠 res 抗魔法）。**只适合给高 res 的魔导师或专职法师**，给牧师则会暴露其脆弱。
- **反 min/max**：res 永久 -1 意味着越用越脆，长线养成中法师会逐渐变成玻璃炮——character-optimization-design 的「thematic emphasis」：力量总有代价。
- **耐久维护（v2）**：20 耐久 + 只能源脉工具修 = 一场硬仗（10-15 次施法）就要消耗一个 repairKit（+15）或回古锻炉——让源脉法杖不是「装上就完事」，而是需要玩家**规划维护路线**。

### 6.2 源脉碎片 sourceVeinShard（传说任务道具 / 一次性）
```
effect: full_mp（回满 MP）
uses: 1
代价: 使用者永久 -1 res（不可逆，跨关卡保留）
```
- **叙事**：吞下源脉碎片，瞬间灵力充盈，但身体被源脉之力撕裂一丝。
- **战术定位**：绝境牌。当 BOSS 战法师 MP 耗尽、翻盘只差一个大招时使用。但永久 -1 res 意味着这个法师以后的培养曲线被永久削低——**玩家会反复纠结要不要用**。
- **设计目标**：让「满 MP」不是免费午餐，呼应「魔法有代价」主题。这是整个道具系统里最锋利的一次性抉择。

### 6.3 虚圣杯 voidChalice（传说消耗品 / 双刃满血）
```
effect: full_hp | full_mp（同时回满 HP 与 MP）
uses: 1
代价: 使用者下一关开始时 power 与 res 各 -2（持续一关，象征「虚空反噬」）
```
- **叙事**：饮下圣杯中的虚素之水，瞬间充盈，但翌日浑身虚脱。
- **战术定位**：关底 BOSS 战的终极续命，但**下一关这个主力会变弱**。若下一关也是硬仗，玩家得权衡：是这关用它翻盘，还是留着？（**跨关资源管理**：典型的延迟满足设计。）

### 6.4 龙骑枪 dragonspear（传说武器 / 屠龙者）⭐新增
```
weaponType: lance
equipStat: power, equipValue: +6
hitBonusMod: -3
durability: 20, maxDurability: 20, repairCost: 12
特殊: 对飞行系（fly）伤害 ×1.8（覆盖职业克制的 ×1.5）
代价: 装备者每关开始时 -1 HP（古龙之血反噬）
```
- **叙事**：以远古龙鳞锻造的长枪，枪尖残留着龙息，专司屠龙——但龙鳞的怨念也会反噬持有者。
- **战术定位**：**反制敌方空军**的终极武器。当敌方派出天马骑士（mov 8、无视地形、切后排如入无人境）时，只有龙骑枪能在其突进前用 ×1.8 伤害一击重创。但 20 耐久 + 每关 -1 HP，让玩家不敢对地用——必须留给「关键空军战斗」。
- **获取**：分支剧情奖励——玩家在第 5 章需在「屠龙者传承」与「源脉神器」两个分支间二选一，呼应**抉择**支柱。

### 6.5 源脉长袍 sourceVeinRobe（史诗装备）⭐新增
```
slot: body
equipStat: res, equipValue: +6
durability: 30, maxDurability: 30, repairCost: 12（仅源脉工具可修）
代价: 装备者每关开始时 -1 HP（源脉侵蚀）
```
- **叙事**：织入源脉丝线的长袍，持续为穿戴者汲取魔力护盾，也持续抽取其生命力。
- **战术定位**：魔法系的「**半肉化**」装备——res+6 让魔导师从 res 6 变 res 12，几乎免疫低阶魔法。但每关 -1 HP 让法师（hp 16-18）逐渐变脆，且耐久只能源脉工具修。
- **与铁甲的对偶**：铁甲（def+4，物理肉）vs 源脉长袍（res+6，魔法肉）——让重甲/法师各有「肉装」，但代价机制不同（铁甲降 mov，源脉长袍降 HP 上限）。

### 6.6 源脉冠 sourceVeinCrown（传说装备）⭐新增
```
slot: helm
equipStat: res, equipValue: +5
durability: 25, maxDurability: 25, repairCost: 10（仅源脉工具可修）
代价: 装备者永久 -1 luk（戴上即生效，不可逆）
```
- **叙事**：源脉冠冕会赐予佩戴者洞察魔法的慧眼，但会吞噬其凡俗的运气——戴冠者能看穿魔力流动，却再也摸不到命运的眷顾。
- **战术定位**：helm 槽的**终极魔防**——res+5 让任何单位（哪怕物理职业）都能扛魔法。但 luk 影响暴击/闪避/掉落，-1 luk 是隐性但长期的代价。
- **反 min/max**：物理职业戴源脉冠获得「**魔法免疫 + 物理暴击下降**」，让「重甲+源脉冠」的坦克 build 有魔法抗性但失去暴击——防止单位变成「又硬又暴击」的全能怪。

### 6.7 源脉神盾 sourceVeinAegis（传说装备）⭐新增
```
slot: shield
equipStat: def +3, res +3（双防）
durability: 20, maxDurability: 20, repairCost: 12（仅源脉工具可修）
代价: 装备者永久 -1 HP 上限（戴上即生效，不可逆）
```
- **叙事**：源脉神盾以持有者的生命力为燃料，凝成一道同时抵御刀剑与魔法的护壁。
- **战术定位**：全游戏唯一的「**双防盾**」——让一个单位同时扛物理和魔法，是「**终极坦克 build**」的核心。但 HP 上限 -1 是永久代价，且耐久只能源脉工具修。
- **build 协同**：板甲（def+6）+ 源脉神盾（def+3, res+3）+ 源脉冠（res+5）= def 9 + res 8 的「**神坦克**」，但 HP 上限 -1 + 板甲 mov -2 agility -2 + 全套源脉装备耐久维护——是「**用机动性和维护成本换绝对防御**」的极端 build，呼应「力量总有代价」。

## 七、经济平衡

### 7.1 掉落与商店定价（reinforcement-feedback-systems 的奖励频率）

| 道具档位 | 每章掉落数量 | 商店定价区间 | 设计意图 |
|----------|-------------|-------------|----------|
| 普通消耗品 | 4-6 个/章 | 50-150 金 | 固定奖励（Fixed Reward），保证基础续航可预测 |
| 精良 | 1-2 个/章 | 300-600 金 | 半变动奖励，精英怪掉落 |
| 史诗 | 0-1 个/章 | 不出售，仅宝箱/BOSS | 变动奖励（Variable Reward），刺激探索 |
| 传说 | 全游戏 3-5 个 | 不出售 | 抉择奖励，绑定分支剧情 |
| **普通武器** | **2-3 把/章** | **150-400 金** | **武器商店主力，耐久 40 廉价耐用** |
| **精良武器** | **0-1 把/章** | **800-1500 金** | **精英掉落，耐久 30** |
| **普通防具** | **1-2 件/章** | **100-300 金** | **防具商店，按 slot 分价** |
| **磨刀石** | **商店常驻** | **80 金/个** | **耐久系统的应急消耗品** |

> **MP 药剂限量**：`mpPotion` 每章商店仅进货 2 个（呼应魔法稀缺）。这是整个经济里**最严的限量**，直接决定法师一关的输出上限。详见 [07 技能·MP 经济](07_skills.md)。

### 7.2 金币产出节奏
- 普通关卡结算：100-200 金
- 精英/BOSS 关：300-500 金
- 分支抉择可额外获得 200 金或一件精良装备（**资源 vs 装备的抉择**）

### 7.3 耐久度对经济的消耗（v2 新增）

耐久度系统会**持续吸金**——这是设计上对「金币通胀」的对冲：

| 装备类型 | 单次修复成本（满修） | 一关平均修复次数 | 年消耗估算 |
|----------|---------------------|------------------|-----------|
| 铁剑（普通）| 40 × 3 = 120 金 | 1 次/2 关 | 60 金/关 |
| 战斧（精良）| 30 × 6 = 180 金 | 1 次/关 | 180 金/关 |
| 源脉法杖（传说）| 20 × 15 = 300 金 + 需源脉工具 | 1 次/关 | 300 金/关 + repairKit |

> **设计意图**：让玩家**不能囤金**——金币总有修复用途，避免「中后期金币爆仓无事可做」的通病（SRPG 经典问题）。玩家每关赚 150 金，其中 60-180 金要留给修复，剩余才用于购买新装备/药剂——**经济自动平衡**。

## 八、反 min/max 与滥用防护（character-optimization-design + reinforcement-feedback-systems）

| 滥用模式 | 防护机制 | 引用原理 |
|----------|----------|----------|
| 囤积药剂无脑刷关 | uses 耗尽即销毁；mpPotion 商店限量；史诗/传说 uses=1 | reinforcement-feedback-systems（负惩罚：移除奖励）|
| 低级角色套高级装备（twinking）| 传说装备带永久属性惩罚（源脉法杖 res -1）；装备互联属性（高攻降命中/降 mov）| character-optimization-design（互联属性 + 主题惩罚）|
| 单一堆 power 形成 dominant strategy | 战斧 -10 hitBonus、力量药剂仅 3 回合、源脉碎片 -1 res 永久 | character-optimization-design（防止单属性统治）|
| 永久死亡前 SL 大法 | 本作鼓励「抉择不可逆」（[00 支柱](00_design_pillars.md)），phoenixDown uses=1 且稀有，是设计上「承认会有人死」的兜底，而非鼓励读档 | reinforcement-feedback-systems（惩罚严重度 High 但有 mitigation）|
| **一把武器砍穿全游戏**（v2 新增）| **耐久度系统：传说武器耐久仅 20，且源脉武器需源脉工具修复；磨刀石 uses=2 稀缺** | **reinforcement-feedback-systems（资源维护负担）+ character-optimization-design（耐久逆相关）** |
| **囤积传说武器不用**（v2 新增）| **传说武器 broken 后效果归零，必须修复才能用；耐久自然衰减逼玩家「现在用」** | **player-psychology-decisions（打击囤积行为）** |
| **重甲无敌墙**（v2 新增）| **防具按被命中次数扣耐久，重甲被打多反而坏得快；板甲 agility -2 必被双击加速损耗** | **character-optimization-design（防护有维护代价）** |

### 8.1 doubling-halving 自检锚点
以下变量是道具系统的**平衡高风险点**，开发期应各做 2×/0.5× 极端测试：

1. **mpPotion 的 power（10）**：×2=20 会让法师每关多放 2 个大招（破坏魔法稀缺）；×0.5=5 会让法师一关只能放 1 个法术（过度稀缺→无聊，违反 flow-state）。预期甜蜜点在 8-12。
2. **elixir 的 uses（1）**：若改为 2，BOSS 战难度断崖式下降；保持 1 是整个史诗档的锚。
3. **sourceVeinShard 的永久代价（-1 res）**：若改为 -2 则无人敢用（道具形同虚设）；改为 0 则破坏主题。1 是经过 doubling-halving 后的收敛值。
4. **普通武器耐久（40）**（v2 新增）：×2=80 会让耐久形同虚设（玩家一关根本用不完）；×0.5=20 会让普通武器比传说还脆（破坏「普通=耐用」的设计语义）。预期甜蜜点在 35-45。
5. **磨刀石修复量（+8）**（v2 新增）：×2=16 会让磨刀石成为「便携满修」（破坏修复系统经济）；×0.5=4 会让磨刀石性价比过低（玩家宁可回城）。预期甜蜜点在 6-10。
6. **板甲 def（+6）**（v2 新增）：×2=12 会让板甲单位彻底无敌（破坏物理威胁）；×0.5=3 会让板甲不如铁甲（+4）。预期甜蜜点在 5-7，配合 mov/agility 双惩罚。

## 九、武器耐久度系统（v2 核心机制）⚔️

> 本节是 v2 最重大的新增机制。耐久度把「攻击/受击」这个最高频的玩法行为**附加资源消耗**，让每一次交锋都带重量——呼应 synergy-thematic-design 的「**战争磨损一切**」主题。

### 9.1 数据字段

每件武器/防具新增以下字段（对齐 `items.json`）：

```json
{
  "id": "ironSword",
  "type": "weapon",
  "durability": 40,        // 当前耐久（初始 = maxDurability）
  "maxDurability": 40,     // 最大耐久
  "repairCost": 3          // 每点耐久的金币修复单价
}
```

### 9.2 耐久消耗规则

| 触发场景 | 武器消耗 | 防具消耗 |
|----------|----------|----------|
| 主动攻击（含反击） | **-1** | — |
| 被敌方命中（无论破防） | — | **-1**（被攻击方所有防具各 -1）|
| 攻击 miss | **-1**（仍消耗）| — |
| 技能施放（魔法系武器）| **-1** | — |
| 受 AoE 命中 | — | **-1**（命中范围内防具各 -1）|

> **设计理由**：
> - **武器攻击 miss 也扣耐久**：呼应「刀剑卷刃不取决于有没有砍中」——让「赌暴击/赌命中」的玩家承受真实磨损成本，防止「miss 重试无成本」。
> - **防具被命中即扣**：让重甲（吸引火力的肉盾）反而比轻甲坏得快——这是对「重甲无敌」的反制，让肉盾 build 也要保养。

### 9.3 broken（损坏）状态

当 `durability` 降到 0 时，装备进入 `broken` 状态：

| 装备类型 | broken 效果 |
|----------|-------------|
| 武器 | equipValue ×0.3（取整）、hitBonusMod -20、**武器特技失效**（如源脉法杖 mpCost -2、龙骑枪 ×1.8 特攻）|
| 防具 | equipValue ×0.5（取整）|

> **关键设计**：broken 装备**不消失**，仍占装备槽，但效果大降。玩家必须主动**修复或更换**。这避免了「武器消失=读档重玩」的挫败（player-error-handling 的「有趣的失败 + 恢复机制」），但保留「不修=废铁」的压力。

### 9.4 耐久度可视化（UI 提示）

呼应 visual-player-guidance（视觉引导）：

| 耐久区间 | 武器图标状态 | 设计意图 |
|----------|-------------|----------|
| 100%-60% | 正常显示 | 无需关注 |
| 60%-30% | 图标边缘泛黄 | 提醒「该修了」|
| 30%-10% | 图标边缘泛橙 + 闪烁 | 警告「快坏了」|
| <10% | 图标边缘泛红 + 强闪烁 | 危急「即将 broken」|
| 0%（broken）| 图标变灰 + 裂纹覆盖 | 明确「已损坏，效果减半」|

> **设计理由**：耐久度是「隐性资源」，若不视觉化玩家会忽略（认知负荷）。用颜色梯度（黄→橙→红→灰）遵循 Fitts 定律的「**状态可感知性**」，让玩家一眼判断「这把武器还能打几次」。

### 9.5 耐久度与心流（flow-state-design-framework）

耐久度系统按章节递进引入，避免新手焦虑：

| 章节 | 引入内容 | 心流阶段 |
|------|----------|----------|
| 第 1 章 | 铁剑（耐久 40），玩家学会「修复」习惯 | Stage 1 入门（低压力学习机制）|
| 第 2-3 章 | 引入精良武器（耐久 30），玩家学会「权衡耐久」 | Stage 2 练习（略增挑战）|
| 第 4 章 | 引入史诗武器（耐久 25）+ 源脉武器（需特殊修复）| Stage 3 心流（完整维护负担）|
| 第 5+ 章 | 传说武器（耐久 20）+ 古锻炉（强化）| 深度策略（build + 维护路线规划）|

## 十、武器分类的设计意图（v2 解耦说明）

> 原设计把武器和防具都塞进 `type:"equip"`，导致：① 数据层无法区分「武器特有字段（weaponType/hitBonusMod）」与「防具有字段（slot）」；② 玩家认知上「装备」是一团模糊概念。v2 强制解耦为三个独立分类，理由如下：

### 10.1 解耦的三大收益

| 维度 | v1（合并）| v2（解耦）| 设计原理 |
|------|----------|----------|----------|
| 数据结构 | 字段混乱（weaponType 出现在防具上无意义）| 武器/防具/饰品各有专属字段 | Hick 定律（**分类清晰降低决策成本**）：玩家一眼区分「这是武器还是防具」|
| 装备槽位 | 模糊（防具间是否冲突？）| 明确（weapon×1 / armor 按 slot / accessory×1）| 配装深度：玩家可组合 weapon+body+helm+shield+accessory = 5 槽 build |
| 耐久规则 | 无法区分（武器和防具耐久规则不同）| 武器（攻击扣）/ 防具（受击扣）/ 饰品（无耐久）| 机制清晰：每种分类的耐久逻辑独立，便于玩家预测 |

### 10.2 装备槽位总览（一个单位的装备上限）

| 槽位 | 数量 | 装备类型 | 说明 |
|------|------|----------|------|
| weapon | 1 | 武器 | 武器绑定 weaponType，必须匹配职业 |
| body | 1 | 防具（身甲）| 重防护，通常带副作用 |
| helm | 1 | 防具（头盔）| 轻防护，通常无副作用 |
| shield | 1 | 防具（盾牌）| 主动防御，影响 agility |
| accessory | 1 | 饰品 | 无耐久，数值补足/机制强化 |

> **配装深度示例**：重骑士的「神坦克 build」= 板甲（body）+ 铁盔（helm）+ 鸢盾（shield）+ 守护之戒（accessory）+ 钢枪（weapon）= def 累计 +19，但 mov -3 / agility -3，机动性归零。这就是 character-optimization-design 的「**互联属性**」在装备层的终极体现——堆防护必然牺牲机动。

## 十一、修复系统（v2 核心机制）🔧

> 修复系统是耐久度的「**恢复机制**」——呼应 player-error-handling 的「**有趣的失败 + 恢复机制**」。没有修复系统，耐久度会变成纯惩罚（玩家挫败）；有了修复系统，耐久度变成「**资源管理博弈**」（player-psychology-decisions 的**三角性决策**）。

### 11.1 修复路径一：金币修复（商店）

**最基础的修复方式**。在任何城镇/商店的「铁匠」界面，玩家可付费修复装备：

```
修复总价 = (maxDurability - durability) × repairCost
```

| 装备 | repairCost | 满修成本（从 0 到满）| 设计意图 |
|------|-----------|---------------------|----------|
| 铁剑 | 3 金/点 | 120 金 | 廉价，鼓励频繁修 |
| 战斧 | 6 金/点 | 180 金 | 中等，精良档定价 |
| 符文之剑 | 10 金/点 | 250 金 | 昂贵，史诗档定价 |
| 源脉法杖 | 15 金/点 | 300 金 + **需源脉工具** | 极贵，传说档 + 特殊修复 |

> **金币修复的设计意图**：提供**可预测的恢复路径**（固定单价），让玩家能算「这关赚的金够不够修」。但传说武器 repairCost 高 + 需特殊工具，让「修传说武器」本身就是一笔大投资——防止传说武器被无脑滥用。

### 11.2 修复路径二：同类武器叠加修复 ⭐核心创新

**用一把同名或同类的武器，喂给另一把武器修复**。规则：

```
被修复武器.durability += 喂入武器.durability（但不超过 maxDurability）
喂入武器销毁（消耗）
```

| 场景 | 操作 | 效果 | 设计意图 |
|------|------|------|----------|
| 同名武器叠加 | 铁剑（耐久 25）+ 铁剑（耐久 40） | 主铁剑 → 耐久 40（满），副铁剑销毁 | **库存优化**：玩家捡到多余同名武器，不必卖店低价，可「喂」给主力修满 |
| 同 weaponType 跨档叠加 | 战斧（耐久 10）+ 铁斧（耐久 30） | 战斧 → 耐久 40（满，受 maxDur=30 限制→30），铁斧销毁 | **降级喂升级**：用低档武器喂高档武器，让低档掉落有价值（不全是垃圾）|
| 跨 weaponType | 铁剑 + 铁斧 | **不允许**（武器类型不匹配）| 防止无脑叠加 |

> **同类武器叠加修复的设计意图（player-psychology-decisions）**：
> 1. **打击囤积行为**：玩家捡到「第二把铁剑」时，面临「留着备用 / 卖店 / 喂主力修满」三选一——逼玩家做决策，而非无脑囤。
> 2. **给低档武器二次生命**：普通武器（铁剑/铁斧）掉落多但数值低，原本是「垃圾」。叠加修复让它们成为「**修复材料**」，提升掉落价值——呼应 reinforcement-feedback-systems 的「**奖励有意义**」。
> 3. **三角性决策**：
>    - **金币修复**：可预测、可随时修、但贵（尤其传说武器）
>    - **叠加修复**：免费、但需要库存、且销毁一把武器（机会成本）
>    - 没有免费午餐——玩家必须根据当前库存和经济状况选最优路径。

### 11.3 修复路径三：战场应急（消耗品/任务道具）

| 道具 | 效果 | uses | 获取 | 适用场景 |
|------|------|------|------|----------|
| **磨刀石 whetstone** | 当前武器 +8 耐久 | 2 | 商店（80 金）| 单武器应急 |
| **便携修理包 repairKit** | 全队武器/防具各 +15 耐久 | 1 | 分支奖励/精英掉落 | 长关卡群体续命 |
| **古锻炉 ancientForgeKey** | 源脉武器**免费**修复 + 强化（+5 maxDurability）| 1（开启地点）| 隐藏关卡 | 源脉武器终极维护 |

> **战场应急的设计意图**：让耐久度系统在「**关卡中途**」也有恢复手段，避免玩家「打到一半武器坏了只能撤退重来」的挫败。但 uses 稀缺（磨刀石 2/关、repairKit 全游戏 2-3 个、古锻炉钥匙 1 个），仍是稀缺资源——呼应 reinforcement-feedback-systems 的「**恢复有代价**」。

### 11.4 修复系统的 UI 流程（visual-player-guidance）

修复界面应遵循 Hick 定律（**3-6 个选项最优**）和 Fitts 定律（**常用操作放大**）：

```
铁匠铺界面：
┌─────────────────────────────────────┐
│  [选择装备]                          │
│  ⚔️ 铁剑 (耐久 25/40) [选中]         │
│  🛡️ 铁甲 (耐久 50/50) [满]          │
│  ⚔️ 战斧 (耐久 0/30) [broken!]      │
│                                     │
│  [修复方式]                          │
│  💰 金币修复：+15 耐久 = 45 金       │
│  🔧 叠加修复：用铁斧(耐久30) → +30   │
│  🪨 磨刀石：+8（剩余 2 个）          │
│                                     │
│  [确认修复]                          │
└─────────────────────────────────────┘
```

> **设计理由**：
> - **三选一修复方式**：金币 / 叠加 / 磨刀石，对应三种资源（金 / 库存 / 消耗品），让玩家一眼看清选项（Hick 定律）。
> - **broken 装备高亮**：战斧（broken）用红色 + 感叹号，吸引玩家优先修（visual-player-guidance 的「**注意力捕获**」）。
> - **确认按钮放大**：Fitts 定律——修复是高频操作，按钮要大、要近。

## 十三、数据迁移备忘（对齐现有 items.json）

现有数据（`godot/data/items.json`）需做以下对齐才能承载本设计，建议主控在 08 README 中追踪：

### 13.1 字段迁移

1. `mightPotion` → 重命名为 `strengthTonic`，`stat` 由 `"str"` 改为 `"power"`（对齐 professions.json）。
2. 装备类（`armorRing/powerRing`）新增可选字段 `weaponType`（默认不限）与 `hitBonusMod`（默认 0）。
3. 新增 `effect` 取值：`revive`（复活）、`full_hp/full_mp`（源脉道具）、`cure_status`（全状态清除，区别于 `cleanse` 仅减益）、`repair_weapon`（磨刀石）。
4. 武器类道具建议新增 `weaponType` 字段做装备职业限制校验。

### 13.2 v2 分类解耦迁移

5. **`type` 字段拆分**：
   - 原 `type:"equip"` 中 `weaponType` 非空的 → 改为 `type:"weapon"`
   - 原 `type:"equip"` 中 `equipStat` 为 def/res 且无 weaponType 的 → 改为 `type:"armor"`，新增 `slot` 字段（body/helm/shield）
   - 原 `type:"equip"` 中无耐久、无 weaponType、无 slot 的（戒指/护符/水晶/靴）→ 改为 `type:"accessory"`
6. **耐久字段新增**：所有 `type:"weapon"` 和 `type:"armor"` 必须有 `durability / maxDurability / repairCost` 三个字段；`type:"accessory"` 不需要。
7. **源脉武器标记**：源脉系列装备（sourceVeinStaff/Crown/Aegis/Robe）新增 `sourceVein: true` 字段，逻辑层据此判断「只能用源脉工具修复」。

### 13.3 迁移示例

**迁移前（v1）**：
```json
{
  "id": "ironSword", "type": "equip", "effect": "equip",
  "equipStat": "power", "equipValue": 2, "weaponType": "sword"
}
```

**迁移后（v2）**：
```json
{
  "id": "ironSword", "type": "weapon", "effect": "equip",
  "equipStat": "power", "equipValue": 2, "weaponType": "sword",
  "hitBonusMod": 0,
  "durability": 40, "maxDurability": 40, "repairCost": 3
}
```

**源脉武器迁移后（v2）**：
```json
{
  "id": "sourceVeinStaff", "type": "weapon", "effect": "equip",
  "equipStat": "power", "equipValue": 4, "weaponType": "anima",
  "hitBonusMod": 5, "sourceVein": true,
  "durability": 20, "maxDurability": 20, "repairCost": 15,
  "special": "elemental_skills_mpcost_minus_2",
  "cost": { "perLevelHp": -2, "permanentRes": -1 }
}
```
