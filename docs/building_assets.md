# 四方向建筑素材

建筑使用独立 `buildings` 层，一栋建筑保存一个实例。普通建筑（例如瞭望塔）整片占地阻挡通行；可进入房屋以室内布局区分地板、门、墙和家具。图片高度与逻辑占地独立；当前仅支持同地图的单层室内，不支持登楼或屋顶站立。

## 唯一输入格式

建筑只接受 **4:1 横排精灵图**，由四个等大正方形帧组成，从左到右为方向 0、1、2、3。描述符必须声明 `render.direction_mode="four_directions"`，并使用 `mode="full"`、`crop=null`。单图、正背两张图片、单张方向图和裁切成单帧的输入均不符合建筑契约。旧石墙正背图不再自动注册成内置建筑，也不会复制帧冒充四向。

工程内置“中世纪瞭望塔”使用 `assets/buildings/medieval_watchtower/sheet.png`，尺寸2048×512，每帧512×512。它由 `parametric-topdown-pixel-architecture` CLI 基于原配方重新导出，yaw=45°、pitch=30°、正交、四方向；材质、参数、种子与抗锯齿设置保持原配方。`recipe.json` 保存本次导出配方。旧45°版本的用户库记录保留，但内置建筑分组隐藏它，使用新的30°版本。

- sheet SHA-256：`3a44869debc92e0d7bbdd3811320e1500611cb549021b355ca9eeee60cb5a377`
- recipe SHA-256：`aab5f39cd0ea17159c47df0914b7c37502cc050ab9b107be2e88787d6e079fa4`

## 导入与内置列表

在素材面板选择“建筑”，导入完整四方向横排图；服务会解码并校验尺寸，再按内容哈希保存。编辑器启动时自动注册内置 sheet，在【地形】的【建筑】分组显示“中世纪瞭望塔”和6×6的“宽敞单层房屋”。重复启动复用同内容条目，保留用户名称、底座宽度、锚点、缩放和占地；只有从未标定的条目才补初始标定。注册返回 `{ok, asset_id, changed}`，已符合目标态时 `changed=false` 且零写入。

既有旧单图／正背建筑不满足新格式，库加载时隔离到旧建筑记录，不自动合成四个方向。要继续使用对应建筑，应先准备真实四向 sheet，再重新导入。

## 单帧标定与方向

```json
{
  "mode": "full",
  "crop": null,
  "direction_mode": "four_directions",
  "pivot": {"x": 0.5068258805742822, "y": 0.8142657649984744},
  "pivot_space": "frame",
  "scale": 1.0,
  "footprint": {"w": 2, "h": 2},
  "ground_width_px": 232.44195804706033
}
```

标定来自CLI预制体导出的地基投影：原点 `(259.49485,416.90407)`，台基投影宽232.44196px，菱形宽高比2:1。锚点以完整单帧画布归一化，四方向共用，避免轮廓包围盒漂移。省略 `pivot_space` 或使用 `content` 时仍相对于单帧非透明内容包围盒。不能以整张2048px sheet计算。
- `footprint.w/h`：地面矩形占地，边长 1..8。实例旋转为奇数时交换宽高。
- `ground_width_px`：单帧底座宽度；0 表示自动使用单帧内容包围盒宽度。挑檐和阳台可能超过底座，因此内置值采用232.44196px。
- `scale`：标定后的额外等比缩放，不改变逻辑占地。

底座目标投影宽度为 `16 * (w+h)` 像素；原始单帧纹理完整保留，显示几何按 `目标宽度 / ground_width_px * scale` 等比缩放，采用最近邻采样；不再提前把512px帧压缩到约141px，镜头放大时可直接采样原图细节。遮挡淡化代理沿用同一显示比例。图片平面朝向相机，不将整张 sheet 拉伸为一栋建筑。

相机只支持四个正交象限，实例 `rotation` 也为 0..3。选择帧的公式是：

```gdscript
var relative_direction := posmod(camera_quadrant - rotation, 4)
```

例如实例旋转 1 时，相机象限 0、1、2、3 分别显示帧 3、0、1、2。转实例和转相机必须用相对方向，不能直接用相机象限取帧。

## 地图与生成示例

地图 `buildings` 保存 `{instance_id, asset_id, x, y, rotation}`，`user_assets` 保存该 sheet 的完整描述符快照。`x/y` 是旋转后占地矩形的左上格，渲染锚点落在该矩形中心。放置必须全范围界内、底面等高，并且不与其他建筑重叠；普通建筑不能压单位，可进入房屋只拒绝墙体和家具与单位冲突。

在工程根目录执行：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --script res://tools/prepare_building_demo.gd
```

工具直接构造快照，并校验、重写专用生成文件 `data/battlefields/building_demo.json`，不创建素材服务，不读取或修改用户素材库，不回退写入用户战场目录。默认使用工程内置 sheet，示例名称为“建筑视觉验收：中世纪瞭望塔”。`--sheet` 仅接受 `res://assets/buildings/` 内随项目分发的资源，快照保留该资源路径并核对内容哈希，保证没有用户素材 blob 时仍能离线显示。外部绝对路径、用户目录和通过 `../` 离开建筑目录的路径均会明确拒绝。

工具仅接受一个可选格式：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --script res://tools/prepare_building_demo.gd -- --sheet=res://assets/buildings/medieval_watchtower/sheet.png
```

旧 `--single`、`--back` 和其他参数会明确报错并退出。单帧或双帧图片即使扩展名为 sheet，也会被尺寸校验拒绝。

## 操作与验收

点击建筑分组中的条目进入连续放置：移动鼠标显示占地预览，单击放置，`T` 切换建筑朝向，`Esc` 退出。越界、建筑重叠、阻挡格压单位或底面不等高时拒绝放置；支持撤销、重做、整栋区域复制与移动。

建筑 billboard 的底座中心以下仍有可见像素。渲染时按不透明内容下缘计算沿正交视线的深度偏移，避免这部分穿入地面被裁掉；屏幕投影、逻辑占地与锚点不变，并保持深度测试开启。此偏移只应用于建筑，植物沿用原路径，遮挡淡化代理继承修正后的中心。

编辑器和常规战场通过共享建筑遮挡控制器检测已放置的可见角色：按实际显示比例、绘制平面深度及相交区域的纹理alpha判断。建筑挡住任何角色时缓动到20%不透明度，所有角色离开后恢复；透明留白不触发，地图重建后重放目标，战斗特写锁定优先。`tests/building_occlusion_contract.gd` 覆盖四视角、实际renderer帧驱动、多角色、恢复、透明角、重建与锁定。

纯 headless 契约 `tests/builtin_building_assets_contract.gd` 覆盖首次单条注册、重复调用零写入、磁盘往返后的用户标定与改名保留、真实单帧导入拒绝、严格四向元数据和保存失败回滚。测试使用唯一临时素材库目录，不接触用户库。

人工验收时在重新加载脚本的地图编辑器中打开示例：检查四个视角和实例四种旋转均按公式选择对应帧；底座贴地、比例正常、背景透明；保存加载后方向、占地与引用保持一致；进入战场后角色绕开建筑。代码断言已验证方向选择与数据契约；当前未做截图或美术验收，初始锚点与遮挡效果仍需人工确认。


## 可进入的单层房屋

【地形 → 建筑】选择“宽敞单层房屋”后可连续放置，`T` 旋转。可直接把角色放在室内地板或门格；墙体和家具格拒绝角色。整栋占地仍用于建筑重叠、选择、复制与移动，保存时只记录一个建筑实例。

打开 `data/battlefields/house_interior_demo.json`：房屋原点 `(4,3)`、室内友军 `(7,6)`、门外敌军 `(7,9)`。地图可经既有预制战场入口加载，角色通过门在同一张地图内进出，不切场景。重新生成示例使用：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --script res://tools/prepare_house_demo.gd
```

室内由素材的 `render.interior` 保存，随描述符快照离线加载；在素材面板调整名称、锚点和缩放会保留室内布局。第一版布局通过数据配置，暂未添加房间绘制面板：

```json
"interior": {
  "enabled": true,
  "rows": ["######", "#....#", "#.F..#", "#....#", "#....#", "##DD##"],
  "reveal_zoom": 1.8,
  "hide_zoom": 1.5
}
```

`.` 是可走地板，`D` 是可走门口，`#` 是墙，`F` 是阻挡家具（目前表现为桌子）。布局宽高必须等于 footprint，边界封墙、非角落门口连通全部地板，禁止非法字符和无门房间；放置在同一站立高度的平地上。底层地形的通行规则保留，例如水地形不会因画出地板而自动变得可走。门、家具和阻挡格均随建筑旋转，寻路使用同一份布局。

相机倍率达到1.8时隐藏完整外观，显示真实格子木地板、低墙和桌子；缩小到1.5时恢复整栋外观，中间区间保持原状态避免抖动。地板贴当前真实柱顶，不将单位抬高一层；占地内植物在显示层隐藏。此切换只影响渲染，角色位置、寻路和存档不受缩放影响。当前切换为直接显隐，低墙均为剖面高度，尚无分层屋顶、室内灯光或多楼层。

房屋由建筑工具CLI的 `castle_medieval house` 导出：单层、8×8米、无门廊/阳台，yaw45°、pitch30°、正交、四方向512px、关闭抗锯齿。资源在 `assets/buildings/spacious_house/`；地基投影宽404.910107px，单帧锚点 `(257.289914,342.914093)`，逻辑占地6×6。完整源图保留，不提前缩小。
