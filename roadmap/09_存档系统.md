# 09 · 存档系统

【功能】
完整存档/读档：章节进度、旗标、角色状态、已解锁职业/技能、自定义内容引用，存 `user://saves/`，主菜单可继续/读档/多存档位。

【难度】★★★★☆（中等偏难）

【详细描述】
- 难点在「确定性契约」：存档引用的内容 ID（章节 ID、技能 ID、旗标键、剧本 ID）必须稳定；若后续改 ID/重排 manifest，需 world version 迁移机制（项目已有先例，沿用其迁移模式）。
- `scripts/core/save_system.gd` autoload：`save(slot)` / `load(slot)` / `list_slots()`，格式 JSON + 手写 sha256 校验字段（防手改损坏，轻量即可）。
- 存档内容分层：`progress`（章节/关卡通关记录）、`flags`（06 的旗标字典）、`roster`（队伍/职业/技能/道具，引用 `data/` 的稳定 ID）、`field_state`（03 的燃烧/冰面等战场临时覆盖层——只在战斗中存档时需要）、`custom_refs`（用户自定义剧情/地图 ID 清单——加载前校验 `user://` 内容还在，缺失则提示）。
- 与现有契约并存：`user://settings.cfg` 保留为设置专用，不混入存档。
- UI：Title 加存档位卡片（3–5 个槽位，显示章节名/游玩时间/截图缩略图可选）。
- 验证：契约测试覆盖 roundtrip（存→读字段逐一相等）、版本迁移（伪造 v1 存档升级 v2）、自定义内容缺失的降级提示。
